# 대휴·프로젝트 이월 — 검토와 원장 반영 분리

Issue #4/#35 후속. 기존 근무 사실 승인, 11/30 프로젝트 후보/근거, source Ledger,
유효기간, 대휴 → 이월 → 당해연차 차감과 정확한 취소 복원을 재사용한다.
기존 migration과 기존 원장을 수정하지 않는다. 새 migration:
`20261126045159_leave_benefit_review_apply.sql` (PR #50 통합 스키마 이후).

## 정책 / 경계

- 주말 실근무(휴게 제외) 240분 이상 0.5일, 480분 이상 1일, 일별 최대 1일.
  승인된 근무의 숫자를 DB에서 다시 읽는다. 이 기능은 **회사 복리후생 대휴**이며
  임금·수당과 상계하지 않는다. 근로기준법 제57조 법정 보상휴가를 인증하지 않는다.
- 사용 가능 기간은 해당 근무연도 1/1~12/31. 지난 연도의 대휴를 현재연도로
  자동 재지급하지 않는다. 기존 미연결 수동/이관 대휴의 양수 지급 이력이 있으면
  이미 사용하여 잔액이 0이어도 원본 매핑 확인 전 새 지급을 차단한다.
- 팀장 본인의 주말근무 승인자 정책은 미확정 상태로 기존 차단을 유지한다.
- 프로젝트 이월은 CONFIRMED 후보, 원본 source 유효기간, 연말 잔여분을 사용한다.
  12/31이 지난 수령연도에만 가능하고 이전 연도 대기 신청·미확정 기초잔액·연말
  이후 원장 변경이 있으면 먼저 대조해야 한다. 프로젝트 종료 후 사용 우선 정책과
  실제 미사용 잔여분의 대조는 관리자의 기록된 검토 사유로 남긴다.
- 당해 ANNUAL/SUBSTITUTE 잔여 source를 전액 차감하고 다음 해 CARRYOVER source에
  동일 일수를 기록한다. 이미 이월받은 CARRYOVER를 반복 연장하지 않는다.
  수령연도 12/31까지 사용 가능하며 자동 권리 소멸·미사용수당 판단은 하지 않는다.

공식 근거 확인 (2026-11-26): [국가법령정보센터 근로기준법 제57조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029728249).
법정 임금 대체에는 근로자대표 서면 합의가 별도로 요구된다. 이 제품의 4/8시간
복지 계산은 그 요건 또는 가산임금 산식을 대신하지 않는다.

## Preview → 별도 반영

`preview_leave_benefit`은 쓰기 없이 근거 ID/버전, 직원별 원장 버전, 기준일,
정책 revision, 일수 및 유효기간을 반환한다. 관리자는 원본·기지급 여부를 대조하고
검토 사유와 확인을 제공해야 한다. `apply_leave_benefit`은 다시 권한을 확인하고
직원 및 근거를 잠근 뒤 계획 전체를 재계산·비교한다. Client의 직원/일수는 권한
판단에 사용하지 않는다. 일수·버전·근거가 달라지면 미리보기를 다시 해야 한다.
이동 source와 지급 근무 각각 unique이며 동일 UUID/내용/actor 재전송은 한 번만
기록한다. 다른 UUID라도 같은 근무/원본 source의 이중 지급은 실패한다.

`reverse_leave_benefit`은 원본을 삭제하지 않고 보상 ADJUSTMENT와 append-only 정정
증적을 기록한다. 지급분이 사용되었거나 다른 이월에 연결되었으면 차단한다.
사용 휴가의 적법한 취소/원본 대조가 먼저 필요하다. 이월 정정은 정확한 이전 source로
되돌리며 그 source의 만료 기간을 연장하지 않는다. 정정한 원본을 자동 재지급하지 않는다.

`cancel_approved_weekend_work`는 LEAVE_MANAGE 관리자가 타인의 승인된 근무를 사유와
버전으로 취소한다. 연결 대휴가 있으면 미사용분의 보상 처리와 승인 취소가 한 transaction이다.
사용분이 있으면 전부 실패한다. 기존 근무 시간/사유와 승인 event를 보존하며 별도의 취소
증적을 남긴다. 취소 후 실제 정정 근무를 새로 등록하고 다른 승인 절차를 거칠 수 있다.

## 권한 / 운영

관리 화면 `/admin/leave/benefits`와 서버 actions/RPC는 LEAVE_MANAGE만 허용한다.
새 operation/reversal/void 증적은 manager-only RLS, 직접 쓰기/anon은 금지한다.
직원에게는 기존 본인 source/ledger를 통해 원장만 보인다. 팀장에게 관리자 원장 권한을
추가하지 않는다. 기존 Google OAuth 및 자동 Gmail/cron 비활성을 유지한다.

이 PR은 코드와 합성 데이터 테스트이다. **실제 직원 지급·이월·데이터 이관·운영 DB
변경은 실행하지 않는다.** 새 migration 적용과 실제 원본 대조는 GPT 검수 후 별도 운영 절차다.
원본이 없는 Wanted Space 2026년 20명의 부여/잔여값을 생성하거나 수정하지 않는다.
과거 수동 지급과 근무의 매핑, 연말 이후 정정자료의 확정은 실제 자료 없이는 자동 판단하지 않는다.

## 검증

`tests/leave-benefits.test.ts`: 읽기 전용 preview, 권한/변조/버전, 원자적 실패 rollback,
중복/재전송, 기지급 이력, 사용 후 정정 차단, 정확 복원, 승인 취소, 이월 보존/유효기간.
PGlite의 competing transaction 검사는 단일 연결 직렬화 결과이며 실제 PostgreSQL
다중 연결 lock 경쟁 검증과 다르다. 배포 전 합성 staging 다중 세션, 원본 대조,
개인별 역할 UAT와 복구 검증은 별도로 남는다. 화면 캡처는 browser 합성 fixture만 사용한다.

## 다음 연도 휴일 달력 유지보수

현재 검증된 휴일 coverage는 2026·2027년이다. 2028년 이후 신청을 열기 전에는
공식 월력요항과 최신 법령·임시공휴일 공고를 대조하고, 출처 URL·검증일·연도 revision을
포함한 새 additive migration을 검수한다. 회사휴일 CRUD로 법정 coverage를 대신하거나
검증되지 않은 미래 날짜를 추정하지 않는다. 합성 테스트로 주말/공휴일/반일 계산,
미지원 연도 차단, 변경된 대기 신청의 재계산·재신청 안내를 확인한 뒤 staging에 적용한다.
기존 승인 신청의 frozen 근무일·차감 원장은 다시 계산하지 않으며 취소는 원래 차감을
복원한다. 대휴·이월 지급 검토나 연차 시뮬레이션 성공이 해당 연도의 휴일 검증을 대신하지
않는다. 상세 출처와 절차는 [PHASE_4B_HOLIDAYS.md](PHASE_4B_HOLIDAYS.md)를 따른다.
자동 외부 달력 수집·Gmail·cron은 활성화하지 않는다.
