# 연차 산정·2027 검증 workspace — dry-run

기준: e5b5d2bd5a44349c4269c516e6a39df1cd7e3b99. 구현/공식 자료 확인일: 2026-11-26.

## 범위와 실제 반영 경계

`/admin/leave/simulation`, `/api/leave-simulation`은 LEAVE_MANAGE 전용 읽기 전용 검증이다. 기존 직원·원장을 조회하고 출근/정책/대사 근거를 메모리 작업 사본으로 입력한다. 새로운 source, grant, 원장, 직원 20명, Wanted Space 원본이나 기초잔액을 생성하지 않는다. 새 DB/migration/RPC/service-role/Storage가 없다. 본 기능에는 apply API 자체가 없다. 체크박스는 로컬 검토 표시이며 승인·지급·급여 상계·법적 사용촉진이 아니다. Google OAuth와 Gmail/cron 비활성을 유지한다.

- [고용노동부 1350 상담](https://1350.moel.go.kr/rtmview.do?id=1000315642): 2026-01-27, 2026-06-23, 2026-09-28, 2026-10-12 답변. 사업장·소정근로시간 적용 요건, 입사일 기준과 회계연도 관리, 중도입사 비례와 퇴직 비교가 실제 취업규칙/사실관계에 의존함을 확인했다.

2027 화면은 현재 확인된 규칙에 대한 시뮬레이션이다. 미래 법령/취업규칙 개정을 예측하거나 회사의 실제 출근 사실을 보증하지 않는다.

## 계산과 unknown

- 직원 ID·입사일·상태·버전은 서버에서 재조회한다. 최종 재직일·적용 요건·출근 증거는 원본 참조와 함께 입력해야 한다.
- 입사 후 최대 11개의 첫해 월별 기간과 완료된 근속 연간 기간을 분리한다. 연간 80% 미달은 해당 기간의 월별 개근 증거가 있어야 계산한다. 없으면 null/미확정이며 0으로 치환하지 않는다.
- 법정 근속 가산은 연간 출근 요건을 충족한 기간에만 적용한다. 윤일 및 월말 입사 월별 기산일은 원본/정책 확인 없이 확정하지 않는다. 기준일 전에 아직 입사하지 않은 직원은 제외 표시한다. 2017-05-30 이전 입사자의 과거 누적은 법령 전환/당시 원본 확인 없이 현행 첫해 규칙을 소급 적용하지 않고 미확정으로 둔다.
- 회계연도는 1/1~12/31. 직전 회계연도 근거와 기준일 근속을 표시한다. 중도입사 비례 분자/분모·처리 방식·원본 참조는 미확정 기본값이다. 선택한 반올림 방식은 회사 정책 확정의 대체물이 아니다.
- 당해에 실제 도래한 첫해 월 개근 후보와 회계연도 후보를 분리 계산 후 합산한다. 서버 DB의 서울 날짜(leave_today)보다 완료되지 않은 출근 기간은 수동 충족 입력도 인정하지 않는다. 미래 기준일 전망 자체는 가능하지만 항상 blocker이고 newDays는 미확정이다. 입력한 원본 참조 문자열은 실제 원본 검증의 증명이 아니다.
- 이전 회계연도 누적 부여 및 당해 기부여 대사 원본이 없으면 중복 부여 검증 차단. 현재 과거/당해 ANNUAL 조정 합계와 각각의 대사 값이 다르면 오류. 이미 부여한 양을 다시 후보에 더하지 않으며 초과분을 회수하지 않는다.
- 원장의 전년 조정/사용/잔여/대휴/이월은 기록된 값이다. 사용 가능 여부·12/31 실제 이월 대상·대휴 신규 지급을 뜻하지 않는다. 이월/대휴 절차가 확인되지 않아 총 지급 예정은 미확정으로 둔다.
- 입사일 누적과 회계연도 누적 비교는 모든 필요한 과거 근거가 있을 때만 숫자로 나온다. 출근율·이관 근거가 없으면 알려진 부분합을 확정 합계로 보이지 않는다.

## 보안·검증·추적

페이지와 preview/export API 각각 LEAVE_MANAGE를 재검증한다. 기존 session client/readRows/RLS를 사용하며 HR Private·휴가 사유/급여/비밀정보를 조회하지 않는다. API는 same-origin, bounded 1 MiB JSON, 허용 필드/숫자/직원/중복/버전 검증 및 private,no-store를 적용한다. 근거/직원/원장 전체 입력의 SHA-256으로 export 시 다시 계산·대조하여 stale 결과를 차단한다. 해시는 원본 파일의 진위를 인증하지 않는다.

기준·근거 변경은 결과와 로컬 검토를 무효화한다. 이전 결과와 현재 후보를 비교할 수 있다. Excel에는 기준/입력 원본 참조/직원 결과/기간별 근거를 보관하며 알 수 없는 숫자는 빈 셀이다. 문자열을 Excel 수식으로 만들지 않는다. 산정 근거는 로그에 출력하지 않는다.

Unit/DB: 순수 engine 및 기존 RLS를 재사용. 신규 unit은 미확정, 가산 상한, 첫해 비례와 월별, 80% 미달 월 개근, 퇴직/윤일/미입사, 중복·stale·원장 대사, JSON bounds와 XLSX 안전성을 검증한다. Browser는 관리자 preview/export/stale/local-review/작업 무변경 및 직원/팀장/전문역할/익명/세션전환/위조 요청을 검증한다. 스크린샷은 합성 fixture만 사용한다. 실제 운영 데이터·2026 Wanted Space 20건·staging 역할 세션 검증은 수행하지 않았다.

원본 입수 후 필요한 절차: 원본 hash·행수/직원 mapping·기존부여/사용/잔여 대사 → 출근/근속/비례 정책 근거 확인 → 2027 시뮬레이션/차이 검토 → 별도 승인된 apply 설계(락/버전/원자성/중복 business key/복원) → 실제 반영. 기존 오프라인 migration dry-run 도구는 원본 대사 원칙만 재사용하며 연차 원본이 없는 현재 자동 파서/가짜 파일을 추가하지 않는다.
