# 프로젝트 휴가 이월 후보 근거 / 검토

이 기능은 휴가 부여·연말 잔액 확정·소멸·급여 처리를 하지 않는다. 11월 30일 ACTIVE 유료 외부 프로젝트 투입 근거와 관리자 검토를 보존하고, 직원에게 본인 상태와 사용 안내만 제공한다.

## 정책과 원본

- 11월 30일 당일 snapshot만 현재 ACTIVE 프로젝트/투입 상태를 근거로 사용할 수 있다. 입사일이 기준일 이전/당일이어야 하며 재직 상태, 프로젝트 기간, 투입 기간이 모두 기준일을 포함해야 한다. 판정에 사용한 직원 입사일·재직 상태·버전을 근거에 고정하고 이후 직원 수정으로 과거 근거를 바꾸지 않는다. 프로젝트 도메인은 기존 유료 외부 고객 업무를 의미한다.
- 당일 이후 과거 기준일은 날짜가 확인된 원본 출처와 실제 투입 대조 확인, 근거상 프로젝트 종료일이 필요하다. 현재 ACTIVE 상태에서 과거 투입을 만들어 내지 않는다. 원본 사실의 정확성은 권한 있는 관리자의 대조 책임이며 시스템이 외부 원본을 자동 인증하지 않는다.
- 연말 전 프로젝트 종료 시 잔여 휴가를 우선 사용한다. 이월 처리 대상은 실제 12월 31일 잔여분만 가능하며, 이 화면은 잔액을 계산하거나 확정하지 않는다.
- 후보의 연도는 11월 30일 근거 기준연도다. 예를 들어 2026년 후보는 실제 2026년 12월 31일 잔여분을 별도로 확정한 뒤 2027년 수령연도 원장으로 지급할 수 있다. 후보 확인 자체는 지급이 아니며, 신규 이월분은 수령연도 12월 31일까지 사용 가능하다. 기간이 확인되지 않은 기존 원장은 사실 확인 전 사용 가능 잔액에서 제외하되 원본 이력을 보존한다.
- 고정 상한, 30/60일 만료, 사용률 기준, 자동 소멸·급여·법적 판단을 추가하지 않는다.

## 보존 / 권한

`leave_carryover_case`는 직원/연도별 현재 검토 상태다. `leave_carryover_evidence`와 `leave_carryover_review_event`는 append-only다. 새로운 근거는 기존 근거를 남기고 검토 중으로 되돌린다. 버전 비교와 transaction lock으로 stale 요청/replay를 거절한다. DB 서버 시각과 auth.uid()를 사용한다.

LEAVE_MANAGE만 생성/정정/검토하며 근거와 메모를 조회한다. 직원에게 본인 case 상태만 허용하고, Team Leader에게 팀원의 case나 원본을 공개하지 않는다. 테이블 직접 쓰기를 금지하고 auth 검사 RPC를 사용한다. 원장/leave_source는 이 기능에서 변경하지 않는다.

## 화면 / 검증

DXT Design System v2 공통 toolbar/table/modal을 사용하는 `/admin/leave/carryover`와 `/leave/carryover`. 서버 권한 검사와 RLS를 함께 적용한다. 민감 근거는 직원 응답에 포함하지 않는다.

`tests/carryover.test.ts`: 기준일 snapshot, 원본 대조, 미래 기준일 차단, immutable 이력, stale replay, cross-user/Team Leader/anon/직접 쓰기 차단, 원장 변화 없음. `tests/e2e/carryover.spec.ts`: 관리자 근거→검토→정정, 과거 근거 보존, 직원 상태/서버 응답 비공개, 권한 없는 RPC/URL 차단. 브라우저 screenshot은 통합 검증 시 생성한다. 로컬 mock/PGlite 검증은 실제 hosted Supabase 검증을 대체하지 않는다.
